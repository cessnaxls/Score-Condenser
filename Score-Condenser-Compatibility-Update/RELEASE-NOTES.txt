Score Condensor — file compatibility update

Maintains existing voice selection, Analyze/rest repair, literal and intelligent transcription, transposition, engraving preview, PDF and MusicXML exports.

Improvements:
- Parses MusicXML measures in their original ordered note/backup/forward timeline, including chords and multiple voices, rather than assuming each voice always begins at zero.
- Reads .xml, .musicxml, .musxml, compressed .mxl, .mid and .midi (format sniffing included).
- Interprets MIDI time signatures and creates per-measure metadata, including notes across barlines.
- Exports selected reductions to MusicXML, compressed MXL, MIDI and PDF.
- Rejects oversized uncompressed MXL score entries and archives with excessive entries.

Limitations:
- MusicXML score-timewise needs conversion to score-partwise before import.
- Format-specific content that isn't part of the current reduction model (lyrics, articulations, complex tuplets, orchestration, dynamics, repeats) is not preserved in reduction exports.
- MIDI export is note/event data and does not include page engraving, instrumental articulation, and tempo automation; default tempo is 120 BPM.
- Exact fidelity is not guaranteed for arbitrary files; these changes were syntax checked, not integration tested with dependencies, because package installation did not complete in this environment.

Deployment: Node.js 22, npm install, npm start. Render uses render.yaml.
